# READMEs are documentation, not notes

Treat every README, regardless of filename case or format, as maintained project documentation for its readers. It is not your scratchpad, task tracker, session memory, or handoff log.

- Do not append progress reports, investigation notes, plans, TODO lists from the current task, test-run logs, agent handoffs, or "what I changed" summaries to a README.
- Keep task updates and completion summaries in the conversation. Do not create another repository file for agent notes unless the user asks for one or project instructions explicitly require it.
- Edit a README only when the user requests a documentation change or the requested work makes its existing project documentation inaccurate or incomplete.
- A justified README change documents durable, reader-facing facts: purpose, supported behavior, installation, configuration, usage, or troubleshooting. Describe the resulting project, not the history of this session.
- Preserve the README's audience, structure, tone, and unrelated content. Update the relevant section instead of adding a task diary or replacing the document with your own summary.
- Reading a README for context does not authorize editing it. If no documentation change is needed, leave it alone.
